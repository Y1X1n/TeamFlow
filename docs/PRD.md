## 1. 背景与目标

### 1.1 背景

学生团队、社团与小型工作室通常用聊天工具 + 表格管理项目：任务状态散落在群聊里，责任人不清晰，截止日期靠口头提醒，新人看不到历史决策。通用工具（Jira、飞书项目）功能过重、配置成本高，且缺少轻量的实时协作体验。

TeamFlow 面向 3–20 人的小型团队，提供「开箱即用的项目空间」：实时看板、任务协作、评论与附件、成员权限、自动化提醒与周报。

### 1.2 产品目标（MVP）

1. **实时看板**：多成员同时在看板拖拽任务，他人操作在 500ms 内可见，并显示在线成员与拖拽状态。
2. **细粒度权限**：4 种角色预设 + 按成员粒度的权限覆盖，服务端每个请求强制鉴权。
3. **事件驱动自动化**：任务分配/截止/评论触发站内通知；定时扫描逾期任务；每周自动生成项目周报；项目活动时间线可追溯。

### 1.3 非目标（MVP 明确不做）

- 甘特图、按工时计费、资源排期（简单工时估算见 §23）
- 多组织（Organization）/ 跨组织协作
- 真实短信/IM 推送（站内通知为主；邮件仅用于用户预览确认后的周报发送，不做自动群发）
- 自定义字段、自定义工作流引擎、自动化规则编排器
- 公开项目、访客链接、移动端 App、离线编辑
- 全文搜索、报表导出（CSV/PDF）
- 项目所有权转让

### 1.4 成功指标（上线后 4 周观测）

| 指标                                 | 目标                                  |
| ------------------------------------ | ------------------------------------- |
| 激活：注册后创建或加入 1 个项目      | ≥ 60%                                 |
| 周活跃：每周至少 1 次看板操作        | ≥ 50% 注册用户                        |
| 协作：含 ≥2 名成员的项目占比         | ≥ 40%                                 |
| 实时性：拖拽变更到其他客户端可见 P95 | ≤ 500ms（局域网）                     |
| 自动化：逾期任务 24h 内产生通知      | 100%（可被去重策略延迟至每 24h 一次） |

## 2. 用户与角色

### 2.1 目标用户

| 画像              | 描述                  | 核心诉求                               |
| ----------------- | --------------------- | -------------------------------------- |
| 学生团队负责人    | 组织课程项目/竞赛团队 | 快速建项目、分配任务、看进度、催截止   |
| 团队成员          | 执行任务的学生        | 清楚"我的任务"、实时看到变更、讨论留痕 |
| 社团/工作室管理者 | 同时管理多个小项目    | 成员权限可控、活动可追溯、周报汇总     |

### 2.2 项目角色

| 角色   | 说明                                                                    |
| ------ | ----------------------------------------------------------------------- |
| OWNER  | 项目创建者，每项目唯一；拥有全部权限，不可被移除/降级（MVP 不支持转让） |
| ADMIN  | 管理者：除删除项目外的全部权限；可管理 MEMBER/VIEWER                    |
| MEMBER | 常规成员：创建/编辑/移动/删除任务、评论、上传附件                       |
| VIEWER | 只读成员：可查看项目、看板、评论、周报，可发表评论                      |

### 2.3 权限目录（Permission Catalog）

权限采用 `资源:动作` 命名，共 17 项：

| #   | 权限键              | 说明                                | OWNER | ADMIN | MEMBER | VIEWER |
| --- | ------------------- | ----------------------------------- | :---: | :---: | :----: | :----: |
| 1   | `project:update`    | 编辑项目名称/描述/颜色              |   ✓   |   ✓   |        |        |
| 2   | `project:archive`   | 归档/恢复项目                       |   ✓   |   ✓   |        |        |
| 3   | `project:delete`    | 删除项目                            |   ✓   |       |        |        |
| 4   | `member:invite`     | 生成邀请、邀请成员                  |   ✓   |   ✓   |        |        |
| 5   | `member:manage`     | 移除成员、修改角色/权限覆盖         |   ✓   |   ✓   |        |        |
| 6   | `board:manage`      | 管理看板列（增删改/排序）           |   ✓   |   ✓   |        |        |
| 7   | `task:create`       | 创建任务                            |   ✓   |   ✓   |   ✓    |        |
| 8   | `task:update`       | 编辑任务标题/描述/优先级/截止/标签  |   ✓   |   ✓   |   ✓    |        |
| 9   | `task:assign`       | 修改任务负责人                      |   ✓   |   ✓   |   ✓    |        |

| 14  | `attachment:upload` | 上传附件                            |   ✓   |   ✓   |   ✓    |        |
| 15  | `attachment:delete` | 删除他人附件（本人附件始终可删）    |   ✓   |   ✓   |        |        |
| 16  | `report:view`       | 查看周报/周期报告                   |   ✓   |   ✓   |   ✓    |   ✓    |
| 17  | `report:generate`   | 手动生成周报；查看团队/他人周期报告 |   ✓   |   ✓   |        |        |

### 2.4 权限规则

1. 有效权限 = 角色预设 ∪ 成员覆盖（`permissionOverrides`），覆盖项为布尔值，显式 `false` 可撤销预设权限。
2. OWNER 固定拥有全部权限，不可覆盖；不可被移除或降级。
3. `member:manage` 的下级规则：OWNER 可管理任意成员；ADMIN 仅可管理 MEMBER/VIEWER（不能修改 OWNER 与其他 ADMIN）；MEMBER/VIEWER 无管理权。
4. 邀请角色：OWNER 可邀请 ADMIN/MEMBER/VIEWER；ADMIN 仅可邀请 MEMBER/VIEWER。
5. 本人创建的评论/附件始终可编辑或删除（评论编辑仅限本人；删除他人需 `comment:moderate` / `attachment:delete`）。
6. 前端仅做展示裁剪，**所有校验以服务端为准**；无权限请求统一返回 `403 FORBIDDEN`。
7. 每个项目至少保留 1 名 OWNER（即 OWNER 不能被移除）。

## 3. 需求范围与功能拆解

### 3.1 功能地图

```
TeamFlow MVP
├── F1 账号与认证（P0）
├── F2 项目管理（P0）
├── F3 成员与权限（P0）
├── F4 任务管理（P0）
├── F5 实时看板（P0）
├── F6 评论与 @提及（P0）
├── F7 附件（P1）
├── F8 通知中心（P0）
├── F9 活动时间线（P1）
├── F10 自动化：逾期提醒 + 周报（P0 逾期 / P1 周报）
└── F11 个人工作台（P1）
```

### 3.2 F1 账号与认证（P0）

**描述**：邮箱 + 密码注册登录；JWT 访问令牌（15 分钟）+ HttpOnly Refresh Cookie（7 天，轮换）。支持退出登录、获取/更新个人资料。

**规则**

- 邮箱全局唯一，大小写不敏感（存储小写）；密码 ≥8 位，含字母与数字。
- 密码使用 `scrypt` 加盐哈希（Node 内置，参数见开发约束），禁止明文/可逆存储。
- 登录失败统一提示"邮箱或密码错误"，不泄露账号是否存在。
- Refresh Token 仅存 SHA-256 哈希；每次刷新轮换并吊销旧令牌。
- 头像暂支持外链 URL（后续可扩展上传）。

**用户故事**

- US-1.1 作为新用户，我可以注册账号，注册成功后直接进入工作台。
- US-1.2 作为用户，我可以登录/退出，刷新页面保持登录。
- US-1.3 作为用户，我可以修改昵称和头像。

**验收标准**

- AC-1.1 重复邮箱注册返回 `409 EMAIL_TAKEN`。
- AC-1.2 密码错误返回 `401 INVALID_CREDENTIALS`，5 次失败后触发限流（15 分钟）。
- AC-1.3 Access Token 过期后，前端自动调用刷新接口续期，用户无感知。
- AC-1.4 修改资料后，看板在线成员头像（awareness）在下次连接时更新。

### 3.3 F2 项目管理（P0）

**描述**：创建项目时自动生成默认看板列「待办 / 进行中 / 已完成」；项目列表展示成员数、任务统计与我的待办；支持归档与删除。

**规则**

- 项目名称 1–60 字符；描述 ≤ 500 字符；颜色为 `#RRGGBB`。
- 删除项目仅 OWNER，二次确认；级联删除任务、评论、附件元数据（对象存储文件异步清理）。
- 归档项目只读（❌ 不允许任务/评论/附件/成员变更），可在列表筛选查看并恢复。
- 归档不影响历史数据读取与周报查看。

**用户故事**

- US-2.1 作为用户，我可以创建项目并立即看到默认看板。
- US-2.2 作为负责人，我可以归档/恢复项目。
- US-2.3 作为成员，我可以在项目列表看到我参与的全部项目。

**验收标准**

- AC-2.1 创建项目后 `GET /projects/{id}/board` 返回 3 个默认列。
- AC-2.2 项目归档后写操作返回 `409 PROJECT_ARCHIVED`。
- AC-2.3 非 OWNER 删除项目返回 403。

### 3.4 F3 成员与权限（P0）

**描述**：通过邀请链接邀请成员（无真实邮件，返回可复制链接）；成员列表展示角色；OWNER/ADMIN 可调整角色与按权限覆盖；支持移除成员（移除后旧 Token 立即失效于业务鉴权）。

**规则**

- 邀请：`expiresAt = now + 7d`，一次性使用；接受后创建成员关系；重复接受返回 `409 INVITE_USED`。
- 邀请邮箱已注册时，站内通知被邀请人；未注册时，注册后凭链接可接受。
- 权限覆盖通过 UI 勾选生成 `{ "task:delete": false, ... }`，服务端按目录校验键名。
- 成员被移除后，其进行中的 WebSocket 连接在 ≤5s 内被断开（服务端广播成员变更，实时层复核）。
- 角色变更/移除均写入活动时间线并向当事人发通知。

**用户故事**

- US-3.1 作为管理员，我可以生成邀请链接并复制给同学。
- US-3.2 作为管理员，我可以单独给某成员开放 `board:manage` 权限。
- US-3.3 作为管理员，我可以移除成员，其立即失去访问权。

**验收标准**

- AC-3.1 被移除成员调用项目接口返回 403/404，WebSocket 收到 `permission-revoked` 并断开。
- AC-3.2 覆盖 `task:move: false` 的 MEMBER 拖拽接口返回 403，但看板可正常查看。
- AC-3.3 OWNER 的覆盖设置被服务端拒绝（`409 OWNER_IMMUTABLE`）。

### 3.5 F4 任务管理（P0）

**描述**：任务包含标题、富文本描述、优先级（LOW/MEDIUM/HIGH/URGENT）、负责人、截止时间、标签、所在列与排序位置。支持创建、编辑、删除、查看详情。

**规则**

- 标题 1–200 字符；描述为 TipTap/ProseMirror JSON（≤ 100KB）；标签 ≤5 个，单个 ≤20 字符。
- 负责人必须是项目成员；可空（未指派）。
- 截止时间 ISO 8601 UTC；允许过去时间（创建即逾期，触发一次逾期通知）。
- 移动至 `isDone=true` 列时自动设置 `completedAt`，移出时清空；进入完成列记 `task.completed` 活动，移出记 `task.reopened`。
- 删除任务软删除（`deletedAt`），30 天内可数据库恢复（MVP 不提供 UI），列表与统计排除已删除。
- 所有写操作产生活动事件；指派变更向新负责人发 `TASK_ASSIGNED` 通知。

**用户故事**

- US-4.1 作为成员，我可以创建任务并指派给同学、设置截止时间。
- US-4.2 作为成员，我可以在任务抽屉查看描述、评论、附件并编辑字段。
- US-4.3 作为成员，我可以按负责人/优先级/关键词在看板上筛选任务（客户端筛选）。

**验收标准**

- AC-4.1 指派给非成员返回 `422 ASSIGNEE_NOT_MEMBER`。
- AC-4.2 移入「已完成」列后任务 `completedAt` 非空，看板卡片显示完成态；移出后清空。
- AC-4.3 无 `task:update` 权限（VIEWER）编辑任务返回 403。

### 3.6 F5 实时看板（P0）

**描述**：项目看板按列展示任务卡片；成员可拖拽任务跨列/列内排序；变更实时同步给所有在线成员；显示在线成员头像与"某人正在拖动某任务"的提示。

**规则**

- 排序位置使用分数索引（fractional index）字符串，服务端计算新位置，避免整列重排。
- 客户端拖拽为乐观更新：先本地移动，调用 `PATCH /tasks/{id}/move`，失败回滚并提示。
- 服务端更新成功后通过 Redis 发布 `task.moved` 事件，实时层写入 Yjs 文档并广播；其他客户端 ≤500ms 可见。
- 并发冲突采用"最后写入生效"（按服务端接收顺序），随后广播收敛；不使用客户端 CRDT 写入（Yjs 文档由服务端权威维护）。
- 在线状态（awareness）：用户 id/昵称/头像/颜色/当前拖拽任务 id；30s 心跳，断线自动清理。
- 开启键盘拖拽（dnd-kit KeyboardSensor）与屏幕阅读器提示。
- 看板单次最多加载 1000 个未删除任务；超出提示使用筛选（MVP 不做分页看板）。

**用户故事**

- US-5.1 作为成员，我拖动任务时其他人即时看到，且能看到谁在线。
- US-5.2 作为成员，我在其他成员拖动任务时看到其头像高亮在该卡片上。
- US-5.3 作为只读成员，我可以实时观看看板变化但无法拖动。

**验收标准**

- AC-5.1 两个浏览器会话，A 拖拽后 B 在 500ms 内看到位置变化（局域网 P95）。
- AC-5.2 B 的在线头像列表在 A 加入后 2s 内出现，A 关闭页面后 30s 内消失。
- AC-5.3 VIEWER 连接 WebSocket 成功但文档为只读，其拖拽调用移动接口返回 403。

### 3.7 F6 评论与 @提及（P0）

**描述**：任务详情内以时间正序展示评论；TipTap 富文本；支持 @项目成员 触发通知；本人可编辑/删除自己的评论；有 `comment:moderate` 可删除他人评论。

**规则**

- 评论正文 ProseMirror JSON，解析 `mention` 节点收集用户 id，仅项目成员有效。
- 评论 ≤ 5000 字符纯文本（服务端从 JSON 提取文本校验）。
- 评论创建/编辑产生活动记录；被 @ 成员收到 `MENTION` 通知；任务负责人（非评论者）收到 `TASK_COMMENTED` 通知。
- 编辑窗口不限，但编辑后显示"已编辑"标记。
- 删除为软删除，UI 显示"评论已删除"占位（保留楼层）。

**用户故事**

- US-6.1 作为成员，我可以在任务下讨论并 @ 同学，对方收到通知。
- US-6.2 作为管理员，我可以删除不当评论。

**验收标准**

- AC-6.1 @ 非成员不产生通知且不报错（忽略该 mention）。
- AC-6.2 他人删除我的评论且无 `comment:moderate` → 403；有权限 → 成功且我收到通知。

### 3.8 F7 附件（P1）

**描述**：任务内上传/下载/删除附件；文件存 MinIO（本地）/ S3（部署）；下载通过 5 分钟有效的签名 URL。

**规则**

- 单文件 ≤10MB，单任务 ≤20 个附件；MIME 允许清单：图片（png/jpeg/gif/webp）、pdf、纯文本/markdown、Office（docx/xlsx/pptx）。
- 服务端校验扩展名 + 文件头（magic number），不一致拒绝；存储对象名随机化，不使用原始文件名作为键。
- 上传经 API 流式写入对象存储（MVP，便于统一鉴权与审计）；下载 302 跳转签名 URL。
- 删除附件删除数据库记录 + 异步删除对象；上传者或被授权者可删。

**验收标准**

- AC-7.1 11MB 文件返回 `413 FILE_TOO_LARGE`；伪造扩展名返回 `415 UNSUPPORTED_FILE_TYPE`。
- AC-7.2 非成员访问下载链接签名 URL 由服务端鉴权拦截；签名 URL 5 分钟后失效。

### 3.9 F8 通知中心（P0）

**描述**：站内通知列表、未读数、单条/全部已读；顶栏铃铛展示未读数；支持类型筛选。

**通知类型**：`TASK_ASSIGNED`、`TASK_COMMENTED`、`MENTION`、`TASK_DUE_SOON`、`TASK_OVERDUE`、`MEMBER_JOINED`、`MEMBER_REMOVED`、`ROLE_CHANGED`、`WEEKLY_REPORT`、`INVITE`。

- 通知含 `payload`（projectId/taskId/commentId/reportId 等），点击跳转对应页面。
- 定时类通知（DUE_SOON/OVERDUE）按 `dedupeKey` 去重：同一任务同一用户 24h 内只发一次。
- 站内信仅保留 90 天（定时清理任务）。

**验收标准**

- AC-8.1 指派任务后负责人 5s 内收到通知（主流程同步写入，唯一索引去重）。
- AC-8.2 逾期任务每天最多提醒一次，即使自动化每 15 分钟运行。
- AC-8.3 未读数接口与列表一致性误差 ≤ 0（同一事务内更新）。

### 3.10 F9 活动时间线（P1）

**描述**：项目维度倒序时间线，记录任务创建/更新/移动/完成、评论、成员加入/角色变更、列变更等事件；游标分页。

**规则**

- 活动只读、不可删除；`payload` 保存渲染所需快照（如任务标题、变更前后值）。
- 事件在业务事务内写入，保证与业务数据一致；通知异步化。
- 保留 180 天（定时归档/清理任务）。

**验收标准**

- AC-9.1 创建任务后时间线首条为 `task.created`，包含操作者与任务标题。
- AC-9.2 游标翻页无重复、无遗漏。

### 3.11 F10 自动化（逾期提醒 P0 / 周报 P1）

**逾期提醒**

- 每 15 分钟扫描 `dueDate < now && completedAt IS NULL && deletedAt IS NULL` 的任务。
- 通知接收人：负责人；无负责人时通知任务创建者。
- 同一任务同一接收人 24h 内仅一次（dedupeKey=`overdue:{taskId}:{userId}:{yyyy-mm-dd}`）。
- 任务被重新指派后，接收人以当前负责人为准。

**周报**

- 每周一 08:00（Asia/Shanghai）为每个未归档项目生成上周报告：新增任务数、完成任务数、逾期任务数、评论数、活跃成员 Top5、成员完成数排行。
- 报告持久化（`WeeklyReport`），向所有有 `report:view` 的成员发 `WEEKLY_REPORT` 通知。
- 支持 ADMIN 手动触发（用于演示与补偿），幂等：同项目同一周重复生成覆盖旧记录。

**验收标准**

- AC-10.1 修改任务截止时间为过去时间，下一次扫描（≤15 分钟）产生逾期通知。
- AC-10.2 手动生成周报两次，数据库仅一条同周记录，通知不重复（dedupeKey 含周起始日）。
- AC-10.3 归档项目不生成周报。

### 3.12 F11 个人工作台（P1）

**描述**：登录后首页展示：我的项目卡片、跨项目"分配给我的任务"（按截止时间排序，标红逾期）、未读通知摘要。

**验收标准**

- AC-11.1 任务被指派/取消指派后，工作台列表刷新可见。
- AC-11.2 逾期任务在工作台显示逾期徽标。

## 4. 核心流程

### 4.1 首次使用

```
注册 → 创建工作台账号 → 创建项目（自动默认列）→ 邀请成员（复制链接）
→ 创建任务并指派 → 成员接受邀请加入 → 看板实时协作
```

### 4.2 拖拽任务（时序）

```
用户 A 拖拽卡片 ──► 本地乐观移动
        └─► PATCH /tasks/{id}/move {columnId, beforeTaskId}
              └─► 服务端鉴权 task:move + 项目未归档
                    └─► 事务：计算新 position、更新 columnId/completedAt、写 Activity
                          └─► Redis 发布 board.task.moved
                                └─► 实时层写入 Yjs 文档（服务端权威）
                                      └─► 所有客户端收到 doc update，B 在 <500ms 看到
A 失败则回滚 UI 并提示；A 也应收到 ws 广播（可用服务端序号忽略重复应用）
```

### 4.3 邀请

```
ADMIN 输入邮箱生成邀请 → 返回链接 /invite/{token}（7 天有效）
被邀请人打开 → 未登录先登录/注册 → POST /invites/{token}/accept
→ 创建 ProjectMember + 活动 + 通知邀请人 → 跳转项目看板
```

### 4.4 逾期提醒

```
BullMQ repeatable job（每 15 分钟）
→ 查询逾期任务 → 按接收人组装通知 → dedupeKey 去重（唯一索引）
→ 写 Notification → 前端轮询/进入页面拉取未读数（MVP 不推送通知 WS）
```
