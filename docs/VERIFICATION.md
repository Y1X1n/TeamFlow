## 3. 验收中发现并修正的问题

| #   | 问题                                                                                  | 修正                                                                                        |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 1   | Hocuspocus 原定 v2，调研显示 v2 已停止维护且 npm latest 已到 v4                       | 锁定 `3.4.4`（server/provider）+ `yjs 13.6.33` + `y-protocols 1.0.7`，整组精确版本          |
| 2   | 原设计将 Hocuspocus 嵌入 Nest HTTP（/collab），Nest 10 不暴露 upgrade，存在抢端口风险 | 改为独立 HTTP/WS 服务端口 **1235**（API 进程引导），Nginx `/collab` 反代；架构图/部署图同步 |

| 4   | 错误格式引用 RFC 7807（已被取代）                                                     | 全量改为 **RFC 9457** Problem Details，扩展 `code/errors/requestId`                         |
| 5   | scrypt 参数 N=2^14 低于 OWASP 建议                                                    | 提升为 `N=2^15, r=8, p=3`（maxmem 64MiB），格式与文档同步                                   |
| 6   | BullMQ jobId 计划含 `:`，违反约束                                                     | 明确 jobId 仅含 `[A-Za-z0-9_-]`，幂等由数据库唯一键兜底                                     |
| 7   | PRD 通知类型缺 `INVITE`                                                               | 补齐，三处枚举一致                                                                          |
| 8   | 邀请失败状态码自相矛盾                                                                | 统一为 410（过期/撤销）/409（已使用/已是成员）/403（邮箱不匹配）                            |
| 9   | Board 截断响应头未进契约                                                              | 已补 `X-Board-Truncated`                                                                    |
| 10  | 删除项目时附件对象键会随级联丢失                                                      | 明确先收集 objectKey 入队再删除                                                             |

## 5. 遗留决策（开发中验证）

1. **Hocuspocus v3 API 细节**：`onAuthenticate`、`beforeHandleMessage`、`onAwarenessUpdate`、`openDirectConnection` 与 `readOnly` 行为需在实现阶段用 v3.4.4 实测（调研已给出源码依据）。
2. **文档重建性能**：1000 任务重建 Y.Doc 目标 <100ms；实现后压测，若超预算再引入内存缓存（不落库）。
3. **scrypt 成本**：N=2^15,p=3 单次约 100–300ms（视机器），仅登录/注册触发；压测确认不会成为瓶颈。
4. **邀请邮箱绑定**：接受邀请要求登录邮箱与邀请邮箱一致；如产品后续希望"链接可转发"，需改契约并评估安全影响。
5. **无离线编辑**：服务端权威模型不支持离线拖拽，已写入非目标与 ADR。
6. **实时多实例**：MVP 单副本；扩容需启用 Hocuspocus Redis 扩展与唯一实例名（协议 §10 已留路径）。
7. **无病毒扫描**：附件仅做类型/大小/魔数校验；生产如需强安全需接入扫描服务（非目标）。
